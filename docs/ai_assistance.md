# D5.12 / §16 — AI Assistance Disclosure

Last updated: 2026-09-07. This file satisfies the brief's AI-assistance
disclosure requirement (allowed with disclosure; still fully
understood and defensible by the team).

## Models / tools used

- Interactive coding agent (an OpenAI-compatible CLI agent) used for
  code generation, documentation drafting, and analysis support across
  Phases 1–5. This is the record we can actually stand behind: the agent
  ran locally, every output it produced landed as a git-tracked file,
  and the full change history of what it wrote is the repository itself
  (git log + `provenance/code.csv`). We do not keep a separate
  transcription archive, so we make no claim about one; the granularity
  of model identifiers in specific turn logs is retained by the tool's
  local history rather than committed here.

## Purpose per artifact class

| Artifact | How AI-assisted |
|---|---|
| Code (`src/adapt/*`, `server.py`, `web/*`, `scripts/*`, `tests/*`, `experiments/*`) | Assisted drafting, refactoring, test authoring |
| Writing (phase plans, dossiers, reports, README, docs) | Assisted drafting, phrasing, and cross-checking of structure |
| Visual assets (figures fig1–fig8) | **No generative AI for figures.** Figures are produced by our own `make_figures.py` from our own measured data (numpy/matplotlib). |
| Research design (hypotheses, experiment matrix, statistics plan) | Assistive drafting; scientific design decisions and content are the team's, and were human-reviewed. |

## Generated code

Substantial code was drafted with AI assistance, then human-reviewed,
run, and tested (93 green tests). The team understands and can defend
every exported function; no "black box" third-party-generated blob is
shipped. Generated code is subject to the same provenance rules
(git history, `provenance/code.csv`) as hand-written code.

## Generated writing

AI assisted drafting several prose deliverables (plans, dossiers,
reports). Every one was fact-checked against primary sources, results
files, and code before inclusion; numbers and claims are verified
against `research/experiments/*/results.json` and the evidence ledger —
no AI-suggested number is published without a real source
(`docs/performance_report.md` measurement-caveat and
`#57 Final data audit` policy in phase5.md are binding).

## Generated visual assets

None generated by generative AI. All figures and UI visuals are either
measured-data plots (ours) or labelled educational renderings of
published structures (`provenance/assets.csv`).

## Human review

Every deliverable was human-reviewed before acceptance: tests run,
live server smoke-tested, docs cross-checked against code/results. The
Phase 5 review gates (D5.1 freeze, D5.2 audit, D5.9 freeze, D5.15
matrix) are designed to catch any claim that cannot be defended.

## Major modifications by humans

Humans made the scientific decisions: central-claim wording, experiment
matrix, interpretation of the R1/R2 reproduction results, honesty
policy for not-reproduced BDH numbers, learning-study design, and all
limitations wording. AI output was iteratively corrected where it
conflicted with evidence.

## Statement the team stands behind

Everything in the repository is understood and defensible by the team.
AI assistance reduced drafting time; it did not supply facts, design
decisions, or results. Falsification criteria, provenance, and the
integrity audits exist precisely so that these claims can be checked.
